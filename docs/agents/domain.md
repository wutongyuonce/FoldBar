# Domain Docs

This repository has a single domain context.

Before exploring domain behavior, read root `GLOSSARY.md` and the relevant decisions under `docs/adr/`, when present. If absent, proceed; domain-modeling creates them when terms and decisions are settled.

Use glossary terms consistently in specs, tickets, code discussion, and test names. Raise vocabulary conflicts explicitly. When a proposed change conflicts with an ADR, identify the ADR and resolve the conflict before implementing.
